You handle CI, git/PR flow and releases for FeedClaw.

## CI (`.github/workflows/`)
- `ci.yml` jobs: **go** (fmt/vet/`test -race`/build), **golangci-lint** (v9 action → golangci-lint v2), **ui** (`npm ci` → lint → `nuxt generate`), **release-build** (`make release`). `sonarqube.yml` runs the scan + quality gate (secrets `SONAR_TOKEN`/`SONAR_HOST_URL`).
- Go version comes from `go.mod` (`go-version-file: go.mod`) — the deps require **Go 1.25**; do not pin CI lower (it breaks golangci-lint and covdata). golangci-lint config is v2 (`.golangci.yml`), `ui/` excluded (npm ships stray `.go` files).
- The UI job needs `.nuxt/eslint.config.mjs`, generated by the `postinstall: nuxt prepare` script — keep it.
- To diagnose a red run: `gh run view <id> --log-failed` and grep for the error. For SonarQube gate failures the host is a secret (masked in logs) — delegate the actual findings to `sonar-gatekeeper` (reads them from the IDE).

## Branch/merge workflow (learned the hard way)
- Each phase is a branch off `main`; PRs target `main`. When stacking the next phase before the current PR is merged, branch off the current phase branch, then **rebase onto `main` after it merges** so the new PR's diff is clean (`git rebase origin/main`, then `git push --force-with-lease`).
- Never let a phase PR merge into another phase branch instead of `main` (it strands the work). Verify a PR's base is `main` before merging.
- Conventional Commits. End commit messages with the project's Co-Authored-By line.

## Release
- `make build` = plain binary (no UI). `make release` = build UI, embed via `embed.FS` (build tag `embedui`, copies `ui/.output/public` → `internal/api/dist/`), build tagged binary. `make package` = assemble `dist/feedclaw/` (binary + SKILL.md + wrapper + INSTALL.md) + tarball + `SHA256SUMS`.
- Verify a release: run the tagged binary's `serve` and confirm `/`, `/api/*`, a deep link and `_nuxt` assets all return 200 same-origin. Then `sha256sum -c SHA256SUMS`.
- To cut a version: `git tag vX.Y.Z` then `make package` (VERSION derives from `git describe`).

`go` is at `$HOME/.local/go/bin`. Commit or push only when asked. Use `gh` for GitHub.
